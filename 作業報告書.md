### Research Findings

- Frameworkは品質のDefaultではなく、繰り返すUI / State coordination ProblemをConventionで解く手段として判断する
- `Web App = SPA`をDefaultにせず、MPA / SPA / HybridをNavigation / shared state / rendering cost / public content等で判断する
- Single Source of Truthは`全Stateを1 Store`ではなく、**FactごとにAuthority / Ownerを1つ**持つ考え方として扱う
- Component / Moduleは固定LOCでなくResponsibility / Information Hiding / Change Localityで分ける
- Feature-based / Layer-basedはUniversal Folder Patternにせず、実際のChange Boundaryから判断する
- EventはDependencyを消すのではなくEvent Contractへ移す。SimpleなLocal FlowではDirect Callも正解として維持する
- Cycle / Hub / God Component / Scattered Functionality等は即Rewrite命令ではなくDiagnosis Signalとして扱う
- RefactorはBehavior維持を原則とする小さな構造変更で、将来Change Costを下げる経済的理由を持つ
- Technical Debtは`汚いCode`全般ではなく、将来変更Cost / Riskを生むLiabilityとして扱う
- `Keep → Local Repair → Refactor → Restructure / Incremental Replacement → Rewrite`を分離する
- RewriteはDefaultにも禁止にもせず、Hidden Requirement / Compatibility / Cutover / Rollback / Incremental optionを比較して判断する
- AI生成速度やGreen TestだけをArchitecture HealthのEvidenceにしない
