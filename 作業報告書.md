### Current Evidence

General task-based UsabilityはGOV.UKのCurrent official guidanceを確認した。

- actual / likely Userに具体Taskを試してもらう
- Taskは現実的・関連性があり、明確なGoalを持つ
- 正解PathをTask本文で教えない
- Facilitatorは誘導せず観察する
- Task completion / time等は必要に応じてBenchmarking可能

Browser Permission / Powerful FeatureはMDNのCurrent documentationを確認した。

- Permission stateだけでなくSecure Context、Permissions Policy、User activation等が利用可否へ影響する
- APIごとにpermission / activation mechanismは同一ではない
- Camera / Microphone等は明示Permissionが必要
- Screen Captureはper-use promptとUser activationが必要
- NotificationはUser gestureに近いRequestを推奨
- Clipboard等はBrowser差がある

Curated non-normative evidence:

- `references/task-based-usability-testing-research.md`
- `references/browser-powerful-feature-permission-research.md`

### 実装

Branch: `reinforce/usability-permissions-20260914`

#### 1. `docs/07` — Task-based Usability Validation

次を追加した。

- Primary Task / UX / IAに重要な不確実性が残る場合だけConditionalにTask observationを使う
- actual / likely Userを可能な範囲で選ぶが、固定人数やFormal LabをCommon Ruleにしない
- TaskをUI操作手順ではなくUser Goalとして書く
- 正解Control / PathをTask本文に含めない
- Facilitatorは先回りせず観察する
- `Unassisted Success / Assisted Success / False Success / Blocked / Abandoned`を区別
- Helpあり成功を自力成功へ読み替えない
- PreferenceよりTask failure / recovery / harmful false successを重視
- Benchmarkは必要なProductだけに使い、Universal thresholdを置かない
- Real User Dataが不要ならDummy / Test Dataを使用可能

#### 2. `docs/06` — Browser Powerful Feature Permission / Capability Access

Browser Permissionを1つのBooleanではなく、次の複合条件として扱うContractを追加した。

```text
API / Browser support
+ Secure Context
+ Document / iframe / Permissions Policy
+ User permission state
+ User activation / per-use requirement
+ Device / OS availability
→ Capabilityを実際に使えるか
```

加えて、Page load時の不要な一括Promptを避け、必要なUser-visible Action付近で最小Capabilityだけ要求するRule、Denied / Revoked / Policy-blocked / Device failureを正常Stateとして扱うRule、Permission取得後もData Minimizationを維持するRuleを追加した。

#### 3. `docs/07` — Browser Capability / Permission Verification

対象APIに該当する範囲で次をTest候補へ追加した。

- unsupported / unavailable
- Secure Context failure
- initial prompt
- granted
- denied
- revoked / changed
- User activation不足
- Permissions Policy / iframe block
- Device unavailable / busy
- per-use prompt

Permission表示だけをSuccess Oracleにせず、実OperationとUI Stateが一致することを要求する。
