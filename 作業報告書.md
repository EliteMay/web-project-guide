## 2026-09-14 Visual Owner Boundary Cleanup

### 目的

2026-09-14 Guide Scope / Routing Auditで残ったMedium Finding `GSR-04`を対象に、`docs/04`と`docs/18`のVisual Workflow重複を解消する。

問題は、Owner Registry上では次の責務分離を宣言していた一方、本文では両方がDesign Direction候補・2〜3案比較・WireframeからDirection確定までのWorkflowを持っていたこと。

- `docs/04` — UI / UX / Accessibility / Visual Quality原則
- `docs/18` — Domain-first Visual Research / Redesign Workflow

### 方針

新しいOwnerは追加しない。

Single Normative Ownerを次へ整理する。

```text
User Goal / IA / Navigation / Task Flow Research
→ docs/22

Visual Domain Research
→ docs/18

Design Direction Contract
→ docs/18

Candidate生成 / 2〜3 Direction比較 / Promote・Reject
→ docs/18

選定Direction / 実装UIのQuality評価
→ docs/04

最低完成Gate
→ docs/17
```

`docs/04`からRuleを単純削除せず、固有のDesign判断軸は`docs/18`へ移し、04には品質原則・評価観点・Accessibility / Responsive等を残す。

### 実装

Branch: `refactor/visual-owner-boundary-20260914`

- `Responsibility Boundary`を追加

- AI向けVisual Workflowでも最終Reviewを`docs/04`へ戻す境界を明確化

#### 2. `docs/04`をUI Quality Ownerへ整理
