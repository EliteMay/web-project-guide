### Resume / Crash Recovery

Resume時は保存済み`state.json`だけを信用せず、Current Evidenceを再取得する。

```text
Stored Runtime State
+
Current Repository / Requirements
+
Current Queue / Assignment / Claim
+
Current Branch / Commit Evidence
↓
resume / blocked / needs_reconcile
```

未記録Worker Branch、Queue revision変更、Claim ownership不一致等、Current Evidenceだけで安全に説明できない状態は`needs_reconcile`へfail closedする。

実装途中のRegression Testで、**Assignment前に正常PauseしたRunまでCrash扱いして`needs_reconcile`へ落とす問題**を検出した。Assignment成立前と成立後を分離し、Current Queueが同じ`queued` / unassigned / idle-or-waiting状態なら正常Resumeを許可し、未記録Worker Branch等の曖昧なCrash痕跡だけを停止対象に修正した。

### Progress / Stuck

Failure後に同じ方法を無条件で繰り返さない。

- Verifier failure / unresolved evidenceからFailure Signatureを正規化
- 前AttemptとのFailure Signature差分をmeaningful progress判断へ利用
- `requireMeaningfulDelta`時は同じRetry strategyを繰り返さない
- 同一Failureが`maxSameFailure`へ到達すると`stuck`
- `stuck`時はowned `working` Taskをformal transitionで`blocked`へ移す

### Budget

Phase Cで扱うBudget:

- `maxIterations`
- `maxSameFailure`
- `maxWallClockMinutes`
- `maxModelTokens`
- `maxExternalCost`

Budget exhaustionはVerifier failureとは分離して`budget_exhausted`として扱う。

Finiteなmodel token / external cost budgetを設定した場合、Implementation / Verification双方のusage evidenceが観測できなければ`0`として成功扱いせず停止する。

### Operator Control / Kill Switch

Control Action:

- `run`
- `pause`
- `cancel`

`pause`はsafe boundaryで停止し、再開時にCurrent Evidenceを再確認する。

`cancel`はKill Switchとして扱い、新しいAttemptを開始しない。Controllerが所有する`working` Taskがある場合はformal Queue transitionで`blocked`へ移す。

### Safety Boundary

Phase CでもPhase Bの`L1_WORKTREE`境界を維持する。

- Primary / Default Branch direct write禁止
- Push禁止
- RuntimeによるPR作成なし
- Merge禁止
- Deploy禁止
- Secret capabilityなし
- unrestricted external network capabilityなし
- protected verifier維持
- allowed / protected path guard維持
- Primary Branch SHA不変をRegression確認
- Sequential single-taskのみ

### Regression Scenarios

Phase C Integration Testで確認:

1. Attempt 1 fail → strategy変更 → Attempt 2 pass → Queue completed
2. 同一Failure反復 → `maxSameFailure` → `stuck` → Queue blocked
3. `maxIterations`到達 → `budget_exhausted`
4. Assignment前`pause` → `run` → 正常Resume → pass
5. Attempt開始前`cancel` → cancelled
6. Pause済みState + 未記録next Worker Branch → `needs_reconcile`
7. Target primary `main` SHA不変
