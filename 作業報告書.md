### Safety Boundary

Phase Bは次をGuardする。

- `autonomyLevel = L1_WORKTREE`
- `workingBranchPolicy = isolated_worktree`
- Primary / Default Branch direct write禁止
- Push禁止
- Merge禁止
- Deploy禁止
- Secret capabilityを付与しない
- unrestricted external network capabilityを付与しない
- `maxParallelWorkers = 1`
- protected verifier必須
- WorkerによるVerifier mutationを許可しない
- `V0_SELF`だけをCompletion Oracleにしない
- allowed path外変更を拒否
- protected path変更を拒否
- Verifier後にWorker projectionがCandidate Commitから変化した場合はPASSにしない
- Verification PASS前にQueueをcompletedへ進めない

### Writer Coordination

Sequential-firstをPolicy文言だけにせず、既存Development ReliabilityのRepository Writer LockをPhase Bでも再利用する。

```text
Current Repository clean / ready
↓
Repository Writer Lock
↓
Queue assignment / claim
↓
Worker execution
```

同一Repositoryで別のReliability / Loop writerがLockを保持している場合は、Queueをmutateする前にfail closedするRegressionを追加した。

外部Processがこの共通Lockを使わずにRepositoryを変更した場合も、Base Branch ref / primary projectionの再確認で成功へ丸めない。

### Verification / Queue Completion

成功経路:

```text
queued
→ assigned
→ working
→ Candidate Commit
→ protected verification PASS
→ ready_for_apply
→ completed
```

Verifierは`status: pass`だけでは不足する。

- Policyのrequired checks
- Taskのvalidation requirements
- 各CheckのPASS
- Worker HEADがCandidate Commitのまま
- Worker worktreeがclean
- Primary Branch SHAが開始時と同じ

を確認する。

Verifier failure / operational failureではTaskをcompletedへ進めない。Claim / Worker Branch / ReceiptはPhase CのRecovery Evidenceとして利用できる。

### Receipt

AttemptごとにMachine-readable ReceiptをData側へ保存する。

Schema:

`schemas/loop-engineering/phase-b-receipt.schema.json`

Default logical path:

`loop-runs/<Owner--repo>/<loopId>/<receiptId>.json`

ReceiptはCurrent Project Stateの第二Source of Truthではない。Resume時はCurrent Repository / Requirements / Queue / Branch / Commitを再取得する。
