## 2026-09-11 Automatic Conversation Resume / Workstream

### 目的

Guide対象の開発作業でChatGPT Conversationが変わっても、Userが毎回「前の会話の続き」「Checkpointを読んで」等を説明せず、利用可能なProject / Agent / Clientが通常の続きの発言から同じ作業系列をRecoveryできるContractとPersistence基盤を追加した。

### 実装

`EliteMay/web-project-data`:

- Conversationとは独立した`workstreams/`層を追加
- Workstream metadata / checkpoint / rebuildable lightweight index Schemaを追加
- Workstream create / checkpoint update / index build / candidate resolve / validation / test toolを追加
- Interaction recoveryへ`primaryWorkstreamId` / `relatedWorkstreamIds` / lifecycle transition / append-only correctionを追加
- canonical `persist-interaction.mjs`をInteraction → Conversation checkpoint → Workstream checkpoint → generated indexまで更新する経路へ拡張
- Workstream Resolution ConfidenceとCurrent write target resolutionを分離
- wrong-resume correction、explicit new work、repository separation、write safetyをRegression Testへ追加

`EliteMay/web-project-guide`:

- 新Ownerを増やさず`docs/23-conversation-handoff-recovery.md`をAutomatic Resume / WorkstreamのNormative Ownerとして拡張
- Workstream lifecycle、作成条件、candidate resolution、Hard Rule、High / Medium / Low Confidence、Silent Resume、User Override、stale state recovery、Security / Platform boundaryを定義
- Workstreamを特定できてもBranch / PR / Commit等のwrite targetが一意でなければ書込み禁止と明記
- `START_HERE.md`へAutomatic Resume routeを追加
- `UNRELEASED.md`へRelease-affecting変更として記録
- Conversation Persistence Regression Guardをnew-Conversation hook boundaryまで検査するよう拡張

### 実装中に検出したFailure

Guide PRの初回CIで`Validate development conversation persistence`だけが失敗した。

原因はOwner 23のPlatform boundaryを`post-response hook`だけから`post-response hook / new-Conversation hook`へ拡張したことで、既存Validatorの旧文言完全一致条件が新しい正しい文面を拒否したため。

Rule側を旧表現へ戻すのではなく、Validatorを「automatic capture boundary」と「automatic resume boundary」の両方を検査するContractへ更新した。修正後PR-head CIは成功した。

### Current Contract

```text
Current User Message
↓
Workstream候補解決
↓
必要なCheckpoint / Interactionだけ取得
↓
Current Repository / Requirements再取得
↓
Workstream Confidence判定
↓
Write Targetを別判定
↓
安全ならSilent Resume
```

Conversation CheckpointとWorkstream CheckpointはRecovery Evidenceであり、ProjectのCurrent Requirements / Code / Branch / PR / Commitの第二Source of Truthにはしない。

### Remaining / Platform Boundary

- Repository側のPersistence / ResolverとGuide側のBehavior Contractは実装済み。
- 通常ChatGPT全体へRepositoryから強制できるPlatform-level new-Conversation hookは存在すると仮定しない。
- Automatic Resume Capabilityを利用できるProject / Agent / Clientでは新しいInteraction開始時にResolver / Recovery Contractを実行する。
- Capabilityがない環境では「自動復帰済み」と偽らず、Current RepositoryからのRecoveryへFallbackする。
