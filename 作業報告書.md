## 2026-09-17 Loop Engineering Runtime Phase D

### 目的

Phase AのRead-only / Dry Run、Phase BのIsolated Worker Loop、Phase CのResume / Stuck / Budget / Controlに続き、**明示的に独立と確認できる複数Taskを安全に並列実行するPhase D Parallel Worker Orchestration**を実装した。

### Parallel Eligibility

Phase Dは`safeParallel=true`だけでは開始しない。

開始条件:

- selected Taskが全て`safeParallel=true`
- selected Task間にdependencyがない
- 外部dependencyがresolved
- Current Requirements revision一致
- 各Laneが利用可能
- `scopePaths[]`がsafeなliteral relative prefix
- Path scopeが相互に重ならない
- `semanticScopes[]`が相互に重ならない
- Policy `allowedPaths`内で、`protectedPaths`と重ならない
- selected Task以外のactive write authorityがない
- `maxParallelWorkers` / Budget内

不明確なTaskを「たぶん独立」と推測して並列化しない。

### Execution Flow

```text
Current Repository / Queue / Requirements
↓
parallel eligibility check
↓
atomic multi-task assignment
↓
formal claim × N
↓
dedicated worker branch / isolated worktree × N
↓
parallel implementation
↓
protected worker verification × N
↓
deterministic Integration Branch
↓
candidate commitsをtaskId順にapply
↓
cross-worker Integration Verification
↓
all PASS -> Queue completion × N
```

Repository-wide writer lockはPhase D Controllerが1つ保持し、外部Writerとの競合を防ぐ。Worker同士は別Branch / worktreeで実装する。

Candidate CommitはTask IDのdeterministic orderで専用Integration Branchへ適用する。cherry-pick conflictは自動解決せずfail closedする。

### Verification / Completion Gate

WorkerごとにTask-specific validation requirements + Policy required checksを満たすprotected verificationを要求する。

Worker全件がPASSしても、Integration Branch上のcross-worker Integration VerificationがPASSするまではQueueを`completed`へ進めない。

Integration Verifier failure / conflict / Budget exhaustion / Cancelではowned Taskをformal Queue transitionで停止し、成功へ丸めない。

### Budget / Kill Switch

Phase Dは全Worker + Integrationをまとめて次のAggregate Budgetで評価する。

- wall-clock
- model tokens
- external cost
- parallel worker count

`cancel`はGlobal Kill Switchとして扱う。

### Safety Boundary

Phase Dでも`L1_WORKTREE`境界を維持する。

- Target Default Branch direct write禁止
- Default Branch SHAを開始時から変更しない
- Worker / Integration Branchはlocal
- Push禁止
- RuntimeによるPR作成なし
- Merge禁止
- Deploy禁止
- Secret capabilityなし
- WorkerによるVerifier改変禁止
- OS-level sandbox / network namespaceはRuntime内蔵と扱わない

### Regression Scenarios

Phase D Integration Testで確認:

1. 2 Worker implementation callbacksが実際に同時進行する
2. 独立Path / Semantic scopeを受理する
3. overlapはQueue mutation前に拒否する
4. Workerごとのprotected verificationを通す
5. Candidate Commitをdeterministic orderでIntegration Branchへ統合する
6. Integration Verifier PASS後だけ全Taskをcompletedへ進める
7. Integration failureではTaskをcompletedにしない
8. Aggregate token budget exhaustionを`budget_exhausted`として停止する
9. Target primary `main` SHA不変
10. Ubuntu / Windows双方で同じContractが成立する

### Validation中に検出した問題

最初のPhase D CIでは、overlap test fixtureがPolicyの`allowedPaths: src/**`に対して`src`を指定しており、overlap判定より先にPolicy外scopeとして正しく拒否された。Test inputを有効scope同士が重なるケースへ修正した。

その後、Phase D test fileがbranch update途中で一時的に欠落する状態を検出し復元した。

Cross-platform validationではWindowsのGit checkoutがCRLFをmaterializeし得るため、fixtureのraw改行完全一致がUbuntuと異なる結果を返した。Runtime Safety Boundaryを緩めず、Testをsemantic content比較へ変更した。
