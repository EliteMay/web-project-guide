`START_HERE.md`ではGuide自身の改善時に`docs/14-continuous-improvement.md`を読むRouteだったが、Machine Routerの`MAINTENANCE`だけでは`docs/14`へ到達できなかった。

対応:

- `CONTINUOUS_IMPROVEMENT` Domain追加
- `CROSS_REPOSITORY_GITHUB` Domain追加
- `MAINTENANCE` Domain追加
- Guide Deep Review Golden Case追加
- Cross-Repository GitHub Maintenance Golden Case追加
- `docs/21`へHuman / Machine Router parity Contract追加

#### 2. Rule移動後の旧Owner Copy残存

前回、公開Site discoverability Ruleを`docs/08-github-pages.md`へ移動したが、`docs/10-project-management.md`にも詳細版が残っておりSingle Normative Ownerが崩れていた。

再評価すると、README / Repository About `Website`等のdiscoverabilityはGitHub Pages固有ではなくHosting方式を問わないProject Management責務。

対応:

- `docs/10`をRepository discoverabilityの正本として維持

#### 3. Project-specific Pilot EvidenceがCommon Ownerへ混入

`docs/16-cross-repository-github-infrastructure.md`へNamed Project、当時の`.github` File一覧、Pilot成功状況、特定ProjectのDependabot例等が混在していた。

Behavioral Ruleとして一般化された内容自体は有用だが、具体Snapshotは時間とともに古くなる。

対応:

- 一般Ruleだけ`docs/16`へ維持
- Named Project / Pilot snapshotを`references/cross-repository-github-pilot-evidence.md`へ非Normative Evidenceとして分離
- 適用時はCurrent GitHubを再確認する境界を明記

- Public SiteをRepositoryから発見しやすくする
- GitHub Pagesの実公開URLを確認し、未確認URLを公開済み扱いしない

- Dependency Updateを通常Quality Gateへ通す
