### R2-01 Production Runtime Observability

`docs/15`へConditionalなProduction Runtime Observability / Operational Readinessを追加した。

- Production Runtime failureがMaterialな場合だけ適用
- `deploy succeeded` / process upだけでなくUser-visible healthを判断できるSignalを持つ
- Metrics / Logs / Tracesを全部必須化せず、Failureを説明できる最小Telemetryを選ぶ
- Multi-component operationでは必要なCorrelation contextを持つ
- AlertをDashboard / information eventと分離し、Human actionが必要なMaterial conditionへ絞る
- TelemetryのSecret / Personal Data / Retention / Cost / Performanceを制御
- User-impacting IncidentをDetection → Impact → Recovery → Root Cause → Monitoring/Test improvement → Learningへ接続

Curated non-normative evidence:

- `references/production-runtime-observability-research.md`
- OpenTelemetry Observability Primer / Logs specification
- Google SRE Monitoring / Practical Alerting / Incident Management guidance

特定Vendor、OpenTelemetry SDK、SLO、Pager、24/7 On-call、Distributed Tracingを全Projectへ強制しない。

### R2-02 Authoritative Write Probe recurrence

`docs/10`へ`Write Capability / Tool Discovery Safety`を追加した。

- Tool schema / read-only API / Repository metadataを先に使う
- authoritative write前にRepository / target ref / current baseを確認
- capability確認だけの`create → delete`をDefault Branchで行わない
- 実Write testが避けられない場合はisolated branch / scratch ref等のnon-authoritative targetを使う
- ProbeがAuthoritative Branchへ入った場合は隠さずRoot Cause Workflowへ通す

今回のRound 2ではread-only確認後にexact baselineからBranchを作成し、`main`へProbeを書いていない。再発Failureとして`PROJECT_LEARNINGS.md`へ`PL-F-017`を追加した。
