## 2026-09-17 Loop Engineering Runtime Phase E / Public Runtime分離

### 目的

Private `EliteMay/web-project-data` のGitHub Actions無料枠を使い切ったことで、Runtime code / Schema / Regression Test / CIとPrivate development dataが同じRepositoryにある構成上の問題が顕在化した。

これを単なるActions回避として扱わず、責務を次へ分離した。

```text
web-project-guide
  Common Rule / Product Contract / Policy Schema

web-project-runtime
  Public reusable Runtime code / Schema / Regression / CI

web-project-data
  Private Conversation / Work Queue / Loop State / Receipt / Evidence / Recovery
```

Phase Eを最初のPublic Runtime migrationとして実施し、Private Data側の重複実装はmergeしない。

### Runtime Phase E

Current Runtime Owner: `EliteMay/web-project-runtime`

Phase EはPhase Dで検証済みのIntegration Branchを`L2_PR`境界でRemote reviewへ公開し、PR / Required Checks / Human Reviewをreconcileしたうえで`ready_for_human_merge`まで進める。

主なGuard:

- passed Phase D Receipt / Integration Verificationを要求
- `autonomyLevel: L2_PR`
- non-force review branch push
- review branchとbase branchの同一指定を拒否
- Remote baseがPhase D検証時点から進んでいれば`needs_reconcile`
- divergent Remote review branchを上書きしない
- PR head / base identityを検証
- Required Check pending / missing → `awaiting_checks`
- Required Check failure / cancellation / timeout / action-required → `blocked`
- Required Checks PASS後もHuman approval不足 → `awaiting_human_review`
- Required Checks + Human approval成立 → `ready_for_human_merge`
- Default Branch direct writeなし
- RuntimeによるMergeなし
- Deployなし
- Receiptは`mergePerformed: false` / `deployPerformed: false`を維持
